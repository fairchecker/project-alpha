# 05. Политика обучения

**Статус:** Draft proposal

## 1. Назначение

Учебные действия помогают пользователю лучше понять концепции, проверить гипотезы и переносить знания на новые задачи. Они должны быть привязаны к реальной работе и не мешать достижению основной цели.

## 2. Независимые настройки

Пример состояния:

```yaml
learning_policy:
  budget: low
  unsolicited_learning:
    enabled: true
    max_per_task: 1
  current_offer:
    status: none
  task_mute:
    enabled: false
```

`budget` ограничивает незапрошенные инициативы, а не право пользователя получать объяснения.

## 3. Интерпретация отказов

- «Не сейчас» — отклонить текущую инициативу.
- «Не обучай меня в этой задаче» — отключить инициативы до завершения текущей задачи.
- «Не задавай учебных вопросов в этом проекте» — изменить проектное предпочтение.
- «Объясни подробнее» — выполнить прямой запрос независимо от бюджета.

Отказ от одного формата не должен автоматически превращаться в бессрочный запрет.

## 4. Рекомендуемые учебные процедуры

### Prediction

До эксперимента пользователь формулирует ожидаемый результат и причину прогноза. После эксперимента прогноз сопоставляется с наблюдением.

### Error Autopsy

После ошибки пользователь при желании формулирует гипотезу о причине. Агент предлагает различающий тест или объясняет ошибку, если дальнейшее самостоятельное исследование неуместно.

### Decision Replay

Пользователь восстанавливает логику ранее принятого решения, после чего сравнивает её с сохранённой записью.

Другие процедуры можно добавить позднее, но не следует превращать все задачи в обязательные упражнения.

## 5. Оценка понимания

Не использовать единственную метрику «может ли пользователь продолжить без модели». Это зависит от доступных инструментов, времени и сложности задачи.

Вместо этого использовать несколько добровольных сигналов:

- `prediction` — прогноз результата;
- `explanation` — способность объяснить ключевую причинно-следственную связь;
- `transfer` — применение принципа к изменённой задаче;
- `continuation` — способность определить следующий шаг.

Это диагностические наблюдения, а не рейтинг пользователя.

## 6. Ограничения

- Не задерживать прямой ответ ради педагогического эффекта.
- Не создавать искусственные препятствия.
- Не навязывать тестирование.
- Не трактовать ошибку как оценку способностей пользователя.
- Не путать краткий ответ с отсутствием обучения: иногда точное решение — лучший способ двигаться дальше.
