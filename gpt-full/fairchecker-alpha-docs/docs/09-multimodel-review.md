# 09. Мульти-модельный обзор

**Статус:** Draft proposal

## 1. Назначение

Мульти-модельный обзор нужен для поиска альтернатив, слабых мест и скрытых предположений. Он не должен превращаться в голосование за истинность.

## 2. Когда запускать

- по явному запросу пользователя;
- при существенном архитектурном выборе, если пользователь заранее разрешил такой триггер;
- когда есть противоречащие источники;
- когда цена ошибки высока и доступна независимая проверка.

Для дорогих или внешних вызовов показывать предполагаемые расходы и запрашивать подтверждение.

## 3. Процедура

1. Подготовить нейтральное описание проблемы и контекста.
2. Получить независимые предложения без раскрытия ответов других моделей.
3. Получить независимую критику вариантов.
4. Сопоставить утверждения, предположения, ограничения и рекомендации.
5. Проверить критичные фактические утверждения через источники или эксперимент.
6. Сформировать отчёт с согласиями и разногласиями.
7. Оставить окончательное решение пользователю, если оно затрагивает цели или компромиссы проекта.

## 4. Что нельзя делать

- Не считать большинство голосов доказательством.
- Не объявлять модели независимыми, если они используют одинаковый источник или общий контекст, создающий коррелированные ошибки.
- Не скрывать существенные разногласия.
- Не отправлять конфиденциальные данные внешним моделям без разрешения.
- Не запускать мульти-модельный процесс для тривиальных задач без причины.

## 5. Структура отчёта

- Общее описание проблемы.
- Совпадающие рекомендации и их основания.
- Существенные разногласия.
- Различающиеся предположения и приоритеты.
- Неподтверждённые утверждения.
- Необходимые эксперименты.
- Возможные последствия каждого варианта.
- Вопрос, который должен решить пользователь.
